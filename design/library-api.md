# Shine as a library: Python and TypeScript API (design)

Status: **agreed**, being built.

## Goals

1. **Everything without the app.** A developer can build components and designs, simulate
   them, sweep, analyse, optimise and export, from a Python script, a notebook, a
   TypeScript/Node program or a web page, with no window.
2. **One model, two views.** What the library builds is a normal Shine project: save it and
   open it in the app to look at it, or open a file made in the app and script it. Nothing
   is lost either way.
3. **Self-documenting.** Names say what things are and units are in the names
   (`wavelength_nm`, `length_um`, `power_mw`). Every object can list what it has
   (`part.params()`, `part.ports()`), and errors say what would have worked. Docstrings
   and JSDoc come from the Rust doc comments.
4. **The same words as the app.** Blocks, ports and parameters use the inspector's and
   sweeps' names (`coupling`, `length`, `n_eff`, `θ`…), so what you see in the app is what
   you type in code.
5. **Native speed.** The bindings call the same Rust engine as the app (Python through a
   native extension, TypeScript through WebAssembly), generated by
   [BoltFFI](https://boltffi.dev).

## A first look

The modulator from the digit recognizer, written in code, then used on a chip:

```python
import shine_photonics as shine

project = shine.Project()

# A component: what it does inside, and the parameters each placed copy sets.
mzm = project.new_component("Modulator")
light_in = mzm.light_input("in")
light_out = mzm.light_output("out")
split = mzm.y_splitter()
heater = mzm.phase_shifter(phase=3.14159)
upper = mzm.waveguide(length_um=100)
lower = mzm.waveguide(length_um=100)
join = mzm.y_combiner()
mzm.chain(light_in, split, heater, upper)
mzm.connect(split.port("out2"), lower.port("in"))
mzm.connect(upper.port("out"), join.port("in1"))
mzm.connect(lower.port("out"), join.port("in2"))
mzm.chain(join, light_out)
mzm.expose("bias", heater, "phase")

# A design that uses it.
chip = project.new_design("Link")
laser = chip.laser(wavelength_nm=1550, power_mw=1)
modulator = chip.place(mzm).set("bias", 0.0)
detector = chip.detector()
chip.chain(laser, modulator, detector)

result = chip.simulate()
print(result.power_mw(detector))          # 1.0: bias 0, the arms add up

sweep = chip.sweep(modulator, "bias", start=0, stop=6.283, points=101)
print(sweep.series("Detector").power_mw)   # the modulator's transfer curve

project.save("link.shine")                 # open it in the app
chip.show()                                # or open the app on it now (desktop)
```

```typescript
import { Project } from "shine-photonics";

const project = Project.new();
const chip = project.newDesign("Link");
const laser = chip.laser(1550, 1);                // wavelength_nm, power_mw
const ring = chip.ring(0.05, 100);                // coupling, length_um
const detector = chip.detector();
chip.chain([laser, ring, detector]);

const spectrum = chip.sweep(laser, "wavelength", 1540, 1560, 2001);
console.log(spectrum.readouts("Detector"));       // FSR, width, Q of the dips
const file: Uint8Array = project.toBytes();       // open it in the app at shine.lupyd.com/app
```

## Concepts

| Concept | What it is | In the app |
|---|---|---|
| **Project** | A `.shine` file: designs and components | File |
| **Design** | One circuit: a top-level design, or a **component** others can place | A tab |
| **Part** | One block placed in a design: built in (coupler, ring…) or a component | A box |
| **Port** | A part's light or signal input or output, by name (`in1`, `through`, `phase`) | A port |
| **Parameter** | A named number of a part, with a unit (`coupling`, `length` µm) | The inspector |
| **Results** | Simulation, transmission, sweep, Monte Carlo, optimisation | Analysis menu |

Conventions, the same as the app's: fields are complex amplitudes with |E|² in mW;
wavelengths in nm, lengths in µm, phases in rad, loss in dB or dB/cm; light runs one way.

## The API

Types are shown in Python; TypeScript has the same names in camelCase (`new_design` →
`newDesign`), `number` for floats, `T[]` for lists and `T | null` for optional values.

### Project

```python
class Project:
    def __init__(self)                              # an empty project
    @classmethod
    def open(cls, path: str) -> Project             # a .shine file (desktop, Node)
    @classmethod
    def from_bytes(cls, data: bytes) -> Project     # a .shine file's contents (browser too)
    def save(self, path: str) -> None
    def to_bytes(self) -> bytes

    def new_design(self, name: str) -> Design
    def new_component(self, name: str) -> Design    # a design others can place
    def design(self, name: str) -> Design           # by name; raises listing the names there are
    def designs(self) -> list[str]

    # Components known by data or by code.
    def new_model_from_touchstone(self, name: str, data: bytes) -> Design   # .sNp
    def new_model_from_lumerical(self, name: str, text: str) -> Design      # .dat / .sparam
    def new_model_from_table(self, name: str, inputs: list[str], outputs: list[str],
                             wavelengths_nm: list[float], matrices: list[Matrix]) -> Design
    def new_model_from_function(self, name: str, inputs: list[str], outputs: list[str],
                                wavelengths_nm: list[float], model: TransferFunction) -> Design
    def new_scripted_component(self, code: str) -> Design   # JavaScript, as in the app (desktop)
```

`new_model_from_function` takes any object with a `matrix(wavelength_nm)` method, written in
Python or TypeScript; Shine samples it at the wavelengths given and keeps the table, so the
component is saved with the project and opens in the app like any other.

### Design

```python
class Design:
    name: str                                       # (a method in TypeScript)
    is_component: bool

    # Built-in blocks: the physics that defines each, the rest set with Part.set.
    def laser(self, wavelength_nm: float, power_mw: float) -> Part
    def detector(self) -> Part
    def coupler(self, coupling: float) -> Part
    def phase_shifter(self, phase: float) -> Part
    def attenuator(self, loss_db: float) -> Part
    def waveguide(self, length_um: float) -> Part           # n_eff 2.4, n_g 4.2, 0 dB/cm unless set
    def mzi(self, theta: float, phi: float) -> Part
    def ring(self, coupling: float, length_um: float) -> Part
    def add_drop_ring(self, coupling: float, length_um: float) -> Part
    def y_splitter(self) -> Part
    def y_combiner(self) -> Part
    def crossing(self) -> Part
    def splitter_tree(self, outputs: int) -> Part           # a power of two
    def switch_tree(self, outputs: int, address: int) -> Part
    def dft(self, modes: int) -> Part
    def value_input(self, value: float) -> Part             # electronics
    def number_input(self, bits: int, value: int) -> Part
    def display(self, bits: int) -> Part
    def register(self, bits: int) -> Part
    def function_cell(self, name: str, inputs: int, light_inputs: int,
                      outputs: list[str]) -> Part           # expressions, as in the app

    def place(self, component: Design) -> Part              # a copy of a component

    # A component's ports (its pins) and its parameters.
    def light_input(self, name: str) -> Part
    def light_output(self, name: str) -> Part
    def signal_input(self, name: str) -> Part
    def signal_output(self, name: str) -> Part
    def expose(self, name: str, part: Part, param: str) -> None

    # Wiring: light ports with waveguides, signal ports with wires.
    def connect(self, source: Port, target: Port) -> None
    def chain(self, *parts: Part) -> None   # each part's first free light output to the next's
                                            # first free light input (a list in TypeScript)
    def disconnect(self, port: Port) -> None
    def remove(self, part: Part) -> None

    def parts(self) -> list[Part]
    def find_part(self, name: str) -> Part                  # by name; raises listing them

    # Analysis.
    def simulate(self) -> Simulation
    def transmission(self, wavelengths_nm: list[float]) -> Transmission
    def sweep(self, part: Part, param: str, start: float, stop: float, points: int) -> Sweep
    def monte_carlo(self, runs: int, seed: int, variation: Variation) -> MonteCarlo
    def optimise(self, variables: list[Variable], output: str, goal: Goal, steps: int) -> Optimised
    def apply(self, variables: list[Variable], values: list[float]) -> None   # what optimise found

    # Other tools.
    def to_touchstone(self, wavelengths_nm: list[float]) -> str
    def to_sax(self, wavelengths_nm: list[float]) -> str
    def to_gdsfactory(self, spacing_um: float) -> str

    def show(self) -> None                                  # open the app on it (desktop)
    def describe(self) -> str                               # its parts, ports and wiring, as text
```

Every built-in block method takes only what defines the block; the rest has the app's
defaults and is set by name, so a call stays short in both languages:

```python
ring = chip.ring(coupling=0.05, length_um=100).set("n_g", 4.2).set("loss", 3)
```

### Part

A component's pins face into it: an input pin's only port is `out` (where its light enters
the component's circuit), an output pin's is `in`. Signal pins likewise: a signal input has
`out`, a signal output `in`.

```python
class Part:
    name: str                       # unique in its design: "Ring resonator", "Ring resonator 2"…
    kind: str                       # "Ring resonator", "Directional coupler", or the component's name

    def port(self, name: str) -> Port               # raises listing the ports there are
    def ports(self) -> list[PortInfo]
    def params(self) -> list[Param]                 # name, unit, value, typical range
    def get(self, param: str) -> float
    def set(self, param: str, value: float) -> Part # returns the part, to chain
    def place_at(self, column: int, row: int) -> Part   # its position in the app (else laid out on save)
```

### Records

Plain data, a dataclass in Python and a read-only object in TypeScript:

```python
@dataclass
class PortInfo:  name: str; kind: PortKind; direction: Direction     # Light/Signal, In/Out
class Param:     name: str; unit: str; value: float; min: float; max: float
class Complex:   re: float; im: float
class Matrix:    rows: int; cols: int; values: list[Complex]          # row by row
class SweepAxis: part: Part; param: str; start: float; stop: float; points: int
class Variable:  part: Part; param: str; min: float; max: float
class Variation: n_eff: float; coupling: float; phase: float; loss: float  # standard deviations
```

`Port` is a small handle (`port.part`, `port.name`, `port.kind`, `port.direction`).

### Results

```python
class Simulation:
    converged: bool
    def power_mw(self, part: Part) -> float         # into a detector or output
    def output_power_mw(self, port: Port) -> float  # leaving any output port
    def signal(self, port: Port) -> float           # a signal output's value
    def display(self, part: Part) -> int            # the number a display shows
    def readings(self) -> list[Reading]             # every detector and output: name, power_mw

class Transmission:
    wavelengths_nm: list[float]; inputs: list[str]; outputs: list[str]
    def field(self, output: str, input: str) -> list[Complex]   # per wavelength
    def power(self, output: str, input: str) -> list[float]
    def phase(self, output: str, input: str) -> list[float]     # unwrapped
    def group_delay_ps(self, output: str, input: str) -> list[float]
    def matrix(self, wavelength_index: int) -> Matrix

class Sweep:
    x: list[float]; x_label: str
    def outputs(self) -> list[str]
    def series(self, output: str) -> Series        # name, power_mw
    def readouts(self, output: str) -> Readouts    # FSR, width, Q, extinction (wavelength sweeps)
    def to_csv(self) -> str

class MonteCarlo:  runs; outputs(); values(output); stats(output); yield_of(output, min, max); to_csv()
class Optimised:   values: list[float]; before: float; after: float; simulations: int
```

### Errors

One exception type, `ShineError` (a `RuntimeError` in Python, an `Error` in TypeScript),
whose message says what went wrong and what would have worked:

```text
ShineError: “Ring” has no port “drop”; it has: in, through
ShineError: “Coupler” has no parameter “kappa”; it has: coupling
ShineError: a waveguide goes from an output to an input: “in1” is an input
ShineError: the design did not settle; a feedback loop may be oscillating
```

## Looking at it in the app

- `project.save(path)` writes a normal `.shine` file. Open it in the desktop app, or in the
  browser app with File → Open.
- `design.show()` saves to a temporary file and starts the desktop app on it (when `shine`
  is installed), then returns; edit there and `Project.open` again to read the changes.
- Parts placed from code have no position. Shine lays the design out when it's saved, left
  to right in the order light flows, so it reads well in the app; `part.place_at(column,
  row)` fixes a position.
- A file made in the app opens in the library with every part's name as the app shows it.

## How it's built

```text
shine (Rust)
├── photonics            the engine (as today)
├── core   [new]         the design model, simulation, analysis, files and exports,
│                        with no window, editor or OS dependencies (feature "core")
├── api    [new]         the interface above: Project, Design, Part…, documented, used
│                        by Rust programs directly and wrapped by the bindings
└── panels               the app: editor, windows, menus (feature "gui"), built on core
bindings/  [new crate]   BoltFFI exports of `api`: Python extension + wheel,
                         WebAssembly + npm package with TypeScript types
```

1. **Core split.** Today the design model and the simulation sit inside the app's modules,
   and each document carries the editor's state. They move to `core`: geometry from
   `emath` (the same types egui uses, so the app is unaffected), documents as plain data,
   the editor's per-document state kept by the app. The app re-exports the old paths, so
   its code barely changes. Touchstone import (rust-rf) and scripted components (QuickJS)
   stay optional features of core.
2. **`api` in Rust**, with tests: the examples above as Rust tests.
3. **Bindings** with BoltFFI 0.26: `shine-photonics` on PyPI (`import shine_photonics`) and
   npm, built in CI for Linux, macOS and Windows, and WebAssembly, and published with each
   release tag. Python and TypeScript test suites run
   the examples above against the built packages.
4. **Docs**: a Python page and a TypeScript page, each a tutorial plus the reference;
   docstrings/JSDoc in the packages.

## Later

- **2-D sweeps** (`sweep_2d`), as the app's sweep window does.
- **Names kept in the file**, so a part can be renamed and the app shows the name: needs a
  file-format version.
- **Free-space parts**, with explicit positions.

## Decided

1. **Names**: `shine-photonics` everywhere: `pip install shine-photonics`, then
   `import shine_photonics` (so it can't collide with the unrelated `shine` on PyPI);
   `npm install shine-photonics`.
2. **Publishing**: with each release tag, to PyPI and npm (the repository needs a PyPI and an
   npm token as secrets).
3. **First version**: waveguide circuits, components and electronics. Free-space parts come
   later, with explicit positions.
4. **Python- and TypeScript-written components** are sampled into tables
   (`new_model_from_function`), so they save and open in the app.
